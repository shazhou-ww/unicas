# UniCAS support

UniCAS is maintained on a best-effort basis without a response or resolution
SLA.

## Where to ask

| Need | Channel |
| --- | --- |
| Reproducible defect | [Bug report](https://github.com/shazhou-ww/unicas/issues/new?template=bug.yml) |
| Feature or compatibility request | [Feature request](https://github.com/shazhou-ww/unicas/issues/new?template=feature.yml) |
| Public integration question | [Support request](https://github.com/shazhou-ww/unicas/issues/new?template=support.yml) |
| Suspected vulnerability | [Private security advisory](https://github.com/shazhou-ww/unicas/security/advisories/new) |
| Unacceptable community behavior | Private channel in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

Do not put credentials, capability tokens, private keys, customer data, or
non-public endpoints in any public issue. Use synthetic identifiers and
redacted logs.

## Supported scope

Support covers the latest documented service behavior and supported package
versions in [SECURITY.md](SECURITY.md). App-user SDK runtime and toolchain
compatibility is documented at
<https://docs.unicas.work/app-user-api/compatibility/>.

Questions about uncommitted forks, retired Stack/Tenant APIs, unsupported
runtimes, or third-party application code may be answered when maintainers
have relevant context, but are not guaranteed. GitHub Discussions is not an
active support channel.

Include a minimal reproduction, exact package versions, runtime and browser
versions, expected behavior, actual behavior, and relevant redacted error
output. Maintainers may convert a support request into a bug or feature issue
when the underlying work is clear.
